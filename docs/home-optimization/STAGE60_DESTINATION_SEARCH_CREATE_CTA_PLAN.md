# v60 여행지 검색 모임 만들기 전환 개선 최종 기획서

- 작성일: 2026-09-04
- 상태: 구현·로컬 검증 완료 / 운영 반영 전
- 우선순위: 우선 수정사항
- 적용 대상: 골프조인 메인페이지 `여행지 검색` 모달
- 서버 API 변경: 없음
- 관리자 대시보드 변경: 없음

## 1. 목표

여행지 검색 이용자가 선택 지역의 기존 모임 일정을 확인한 뒤 날짜나 세부 조건이 맞지 않아도 검색을 종료하지 않고, 선택한 지역을 유지한 채 `새 모임 만들기`로 이어지게 한다.

핵심 원칙은 다음과 같다.

1. 선택 지역에 참여 가능한 모임이 있으면 기존 상품카드를 최우선으로 보여준다.
2. 상품카드 아래에만 보조 전환 영역을 추가한다.
3. 선택 지역에 모임이 없으면 지역명을 포함한 빈 결과 안내와 생성 버튼을 보여준다.
4. 선택 지역과 무관한 추천 일정은 `다른 지역` 추천임을 제목에서 명확히 알린다.
5. 로그인 전후에도 선택한 지역을 잃지 않는다.
6. 일정 있음·일정 없음의 생성 안내는 현재 일정 없음 화면의 UI를 그대로 재사용하고 문구만 상태별로 변경한다.

## 2. 확정 문구

| 상태 | 요소 | 문구 |
|---|---|---|
| 일정 있음 | 안내 제목 | `원하는 일정이 없나요?` |
| 일정 있음 | 안내 설명 | `원하는 상품과 날짜로 직접 모임을 만들어 보세요.` |
| 일정 있음 | 버튼 | `{지역명}에 모임 만들기` |
| 일정 없음 | 빈 결과 제목 | `{지역명}에는 아직 참여 가능한 모임이 없어요.` |
| 일정 없음 | 빈 결과 설명 | `원하는 상품과 날짜로 직접 모임을 만들어 보세요.` |
| 일정 없음 | 버튼 | `{지역명}에 모임 만들기` |
| 일정 없음 | 하단 추천 제목 | `다른 지역에서 바로 참여 가능한 모임` |

지역명은 검색값 전체가 아니라 화면에 표시하는 대표 지역명을 사용한다.

- `나트랑, 베트남` 또는 `나트랑(베트남)` → `나트랑`
- `발리, 인도네시아` 또는 `발리(인도네시아)` → `발리`
- HTML 출력과 `onclick` 인자는 각각 기존 `escapeHtml`, `escapeJsString` 규칙으로 이스케이프한다.

## 3. 화면 상태별 구성

### 3.1 선택 지역에 일정이 있는 경우

표시 순서는 다음과 같다.

1. 검색 지역과 정렬 영역
2. 기존 상품 수와 상품카드
3. `원하는 일정이 없나요?` 보조 전환 영역
4. 모달의 남은 여백

보조 전환 영역은 기존 상품 그리드 바로 아래에 배치한다. 기존 상품 참여가 주 행동이며, 새 모임 생성은 보조 행동으로 유지한다.

레이아웃은 현재 일정 없음 화면 상단의 생성 안내 박스를 그대로 사용한다. 좌우 분할형 신규 디자인을 만들지 않으며, 제목·설명·버튼을 모두 중앙 정렬한다.

```text
1개 상품                         추천순  낮은가격순  마감임박순
[기존 상품카드]

[                  원하는 일정이 없나요?                   ]
[      원하는 상품과 날짜로 직접 모임을 만들어 보세요.      ]
[                {지역명}에 모임 만들기                    ]
```

노출 조건:

- `results.length > 0`
- `regionSearchContext !== "mdpick"`
- 지역명이 유효할 때만 버튼을 노출한다.
- 마크업과 스타일은 일정 없음 생성 안내와 동일한 공통 renderer를 사용한다.

### 3.2 선택 지역에 일정이 없는 경우

기존 빈 결과 영역의 고정 문구를 동적 지역 문구로 교체한다.

```text
{지역명}에는 아직 참여 가능한 모임이 없어요.
원하는 상품과 날짜로 직접 모임을 만들어 보세요.
[{지역명}에 모임 만들기]

다른 지역에서 바로 참여 가능한 모임
[기존 다른 지역 추천 카드]
```

기존 다른 지역 추천 카드의 선정·정렬·상세 진입 동작은 변경하지 않는다. 제목만 변경해 선택한 지역의 결과로 오해하지 않게 한다.

일정 있음 화면과 일정 없음 화면의 생성 안내 박스에서 달라지는 값은 제목뿐이다.

| 항목 | 일정 있음 | 일정 없음 |
|---|---|---|
| 제목 | `원하는 일정이 없나요?` | `{지역명}에는 아직 참여 가능한 모임이 없어요.` |
| 설명 | 동일 | 동일 |
| 버튼 | `{지역명}에 모임 만들기` | `{지역명}에 모임 만들기` |
| 배경·폰트·간격·버튼 | 현재 일정 없음 UI 그대로 | 현재 일정 없음 UI 그대로 |

### 3.3 검색어가 없거나 유효하지 않은 경우

- 빈 검색어 안내는 현재 동작을 유지한다.
- 지역명이 확정되지 않은 상태에서는 동적 생성 버튼을 만들지 않는다.
- `mdpick` 검색 결과와 ERP 상품 없음 화면은 이번 변경 범위에서 제외한다.

## 4. 생성 버튼 동작

두 상태의 생성 버튼은 동일한 진입 함수를 사용한다.

1. 클릭 당시의 확정 지역을 별도 인자로 캡처한다.
2. 여행지 검색 모달을 닫는다.
3. 새 모임 만들기 모달을 연다.
4. 선택 지역을 `builderState.region`, `regions`, `dateConstraintRegions`에 적용한다.
5. 기존 `regionDateFirstMode`를 유지해 해당 지역의 출발 가능 날짜부터 보여준다.
6. 이용자는 출발일 한 날짜만 선택한다.
7. 선택한 지역·출발일에 예약 가능한 상품을 보여준다.
8. 상품 선택 시 그 상품의 귀국일과 여행기간을 자동 적용한다.
9. 지역에 맞는 상품 탐색 데이터를 불러온 후 캘린더를 다시 그린다.

귀국일을 직접 선택하게 하지 않는다. 항공팩 상품은 출발일별 귀국일과 여행기간이 정해져 있어 임의의 귀국일을 허용하면 실제로 존재하지 않는 상품 조합이 만들어질 수 있기 때문이다.

DOM 입력값을 모달을 닫은 뒤 다시 읽지 않는다. 버튼 생성 시점의 지역값을 함수 인자로 전달해 재렌더링과 모달 종료 사이의 상태 경쟁을 방지한다.

## 5. 비로그인·로그인 복귀 보존

현재 `openBuilderFromRegionSearch()`는 메모리의 `pendingBuilderRegion`을 사용한다. 같은 페이지의 로그인 모달에서는 유지되지만 카카오 로그인처럼 페이지를 다시 거치는 경로에서는 지역이 소실될 수 있으므로 다음 계약을 추가한다.

- 로그인 요구 시 `afterLogin=builder`
- `builderAction=region-search`
- `builderRegion={선택한 전체 지역값}`
- 로그인 복귀 파서에서 `builderRegion`을 읽고 URL에서 정리한다.
- `continueBuilderAfterLogin()`의 `region-search` 분기에서 동일한 지역 우선 생성 상태를 복원한다.
- 복귀 실패 시 지역 없는 일반 빌더로 조용히 전환하지 않고, 생성 모달을 연 뒤 지역 선택 단계에서 사용자가 재선택할 수 있게 한다.

보안 규칙:

- `builderRegion`은 UI 선택값으로만 사용하며 서버 권한 판단에 사용하지 않는다.
- 허용 길이 제한과 문자열 정규화를 적용한다.
- HTML과 JavaScript 출력 시 기존 이스케이프 함수를 사용한다.

## 6. 확정 UI·스타일 계약

### 단일 생성 안내 컴포넌트

일정 있음과 일정 없음에 별도 디자인을 만들지 않는다. 현재 일정 없음 화면에서 사용하는 다음 UI를 공통 컴포넌트로 재사용한다.

- 외곽 박스: 현재 `.region-result-empty`
- 문구 래퍼: 현재 `.region-result-empty-copy`
- 제목: 현재 `.region-result-empty-title`
- 설명: 현재 `.region-result-empty-action-line`
- 버튼: 현재 `.region-result-empty-action`

따라서 다음 항목은 두 상태에서 완전히 동일해야 한다.

- 외곽 박스의 배경색, 테두리, 모서리 반경, 높이와 내부 여백
- 제목의 글꼴, 크기, 굵기, 색상과 행간
- 설명의 글꼴, 크기, 굵기, 색상과 상하 간격
- 버튼의 배경색, 글꼴, 크기, 굵기, 높이, 너비와 모서리 반경
- 버튼의 기본색뿐 아니라 `hover`, `focus-visible`, `active`, `disabled` 상태의 배경색·글자색·테두리도 현재 일정 없음 버튼과 동일
- 제목·설명·버튼의 중앙 정렬과 세로 배치
- PC·모바일 반응형 동작

일정 있음 화면에서는 상품 그리드 아래에 동일 컴포넌트를 삽입하는 데 필요한 위쪽 간격만 추가한다. 기존 UI 값을 복사한 새 CSS를 만들지 않고 같은 클래스를 직접 사용해 향후 스타일 변경도 두 상태에 동시에 반영되게 한다.

금지 사항:

- 아이콘 추가
- 문구 왼쪽·버튼 오른쪽의 가로 분할
- 일정 있음 전용 버튼 크기 또는 색상
- 일정 있음 버튼에 별도 색상값, 투명도, 그라데이션 또는 상태별 색상을 추가하는 것
- 일정 있음 전용 제목·설명 폰트
- 비슷한 값을 복제한 별도 CSS 클래스

### 접근성

- 생성 버튼은 실제 `<button type="button">`을 사용한다.
- 버튼의 접근 가능한 이름에 지역명이 포함되어야 한다.
- 키보드 `Tab` 순서는 상품카드 다음 생성 버튼, 이후 다른 지역 추천 카드 순서로 유지한다.
- 모바일에서 긴 지역명은 버튼 텍스트를 두 줄로 만들지 않고 말줄임 또는 안전한 최대 폭을 적용한다.

## 7. GA4 측정

신규 이벤트를 추가하지 않고 기존 생성 퍼널을 사용한다.

- 생성 모달 시작: `golfjoin_create_start`
- `source_area`: `destination_search`
- `flow_type`: 기존 전역 보강값 `new_schedule`
- 후속 단계: `golfjoin_create_step_view`
- 완료: `new_schedule_complete`

필수 수정:

- 여행지 검색 버튼에서 빌더를 열 때 `openModal("builderModal", { analyticsSourceArea: "destination_search" })`와 동등한 계약을 적용한다.
- 일정 있음과 일정 없음 양쪽 버튼이 동일한 `source_area`를 사용한다.

검증 지표:

1. 여행지 검색 실행 사용자
2. `destination_search` 출처의 새 모임 시작 사용자
3. 날짜 선택 단계 도달 사용자
4. 상품 선택 단계 도달 사용자
5. 새 모임 생성 완료 사용자

## 9. 테스트 시나리오

### 기능

- [ ] `나트랑`처럼 일정이 있는 지역에서 상품카드 아래 안내 영역이 보인다.
- [ ] 일정 있음 버튼은 `나트랑에 모임 만들기`로 표시된다.
- [ ] `발리`처럼 일정이 없는 지역에서 확정 빈 결과 문구가 보인다.
- [ ] 일정 없음 버튼은 `발리에 모임 만들기`로 표시된다.
- [ ] 다른 지역 추천 제목이 `다른 지역에서 바로 참여 가능한 모임`으로 표시된다.
- [ ] 다른 지역 추천 카드의 상품·가격·상세 진입은 기존과 동일하다.
- [ ] 지역을 다시 선택하면 문구와 버튼 지역명이 즉시 바뀐다.
- [ ] 두 상태의 안내 박스가 동일한 마크업 계층과 CSS 클래스를 사용한다.
- [ ] 두 상태의 제목·설명·버튼 스타일과 위치가 픽셀 수준으로 동일하다.
- [ ] 두 상태 버튼의 기본·hover·focus-visible·active·disabled 색상이 동일하다.
- [ ] 일정 있음 안내 박스에는 아이콘이나 가로 분할 레이아웃이 없다.

### 로그인

- [ ] 로그인 이용자는 선택 지역이 적용된 생성 캘린더로 바로 이동한다.
- [ ] 비로그인 일반 로그인 후에도 선택 지역이 유지된다.
- [ ] 비로그인 카카오 로그인 복귀 후에도 선택 지역이 유지된다.
- [ ] 필수 회원정보 입력 화면을 거친 후에도 선택 지역이 유지된다.
- [ ] 로그인 취소 시 여행지 검색 화면을 다시 사용할 수 있다.
- [ ] 선택 지역 생성 화면에서는 출발일만 선택한다.
- [ ] 상품 선택 후 귀국일과 여행기간이 상품 데이터로 자동 적용된다.

### 반응형·접근성

- [ ] PC에서 상품카드와 안내 영역의 좌우 정렬이 일치한다.
- [ ] 모바일에서 안내 문구와 버튼이 겹치지 않는다.
- [ ] 긴 지역명에서 버튼이 모달 밖으로 넘치지 않는다.
- [ ] 키보드만으로 생성 버튼과 다른 지역 추천 카드에 접근할 수 있다.

### 분석

- [ ] 버튼 클릭 후 `golfjoin_create_start`가 한 번만 발생한다.
- [ ] `ep.source_area=destination_search`가 포함된다.
- [ ] 로그인 복귀 과정에서 생성 시작 이벤트가 중복 발생하지 않는다.

## 10. 배포·복구 계획

1. 소스 조각과 단위 테스트를 먼저 수정한다.
2. 소스 번들 생성 후 인라인 JavaScript 문법 검사를 수행한다.
3. 배포 HTML, Brotli JavaScript, 복구 HTML을 함께 만든다.
4. Cloud Storage에 새 해시 경로로 JavaScript를 업로드한다.
5. 사용자가 운영 HTML을 직접 교체한다.
6. 일정 있음·일정 없음·비로그인 로그인 복귀를 운영에서 확인한다.
7. 이상 시 직전 운영 HTML로 복구한다.
