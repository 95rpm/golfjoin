# 골프조인 GA4 인사이트 대시보드 v55 기획

기준일: 2026-09-02  
대상 속성: `552152254`  
목표: 초보 운영자도 조인 페이지에서 사용자가 어디서 멈추는지, 무엇을 먼저 개선할지, 어떤 마케팅 유입을 확대할지 판단할 수 있게 한다.

## 1. 이번 감사의 결론

- GA4 응답 연결은 정상이다. 운영 응답은 `ok=true`, `quality.partial=false`, 경고 없음이며 속성 ID도 일치한다.
- 현재 핵심 사용자 수와 단순 도달률 계산은 코드와 응답이 일치한다.
- 다만 현재 퍼널은 각 이벤트의 활성 사용자를 독립 집계한 값이다. 동일 사용자가 앞 단계를 거쳐 다음 단계로 이동했는지를 보장하는 순차 코호트 전환율은 아니다.
- 검색·로그인 퍼널은 중간 단계가 앞 단계보다 커져 `250%`, `200%`가 나타난다. 이 값은 오류 응답이 아니라 독립 이벤트 집계의 한계이며, 초보 운영자용 화면에서 전환율로 보여주면 안 된다.
- 현재 가장 강한 개선 신호는 `상품 상세 → 신청 시작` 구간이다. 상세 열람 105명 중 신청 시작 2명으로 단순 도달률은 1.9%다. 단, 상세 열람에는 빌더 상품 열람이 섞일 수 있으므로 메인 유입만 분리한 뒤 최종 우선순위를 확정한다.
- 마케팅 표는 방문·세션만 제공해 신청 시작·완료까지 연결할 수 없다. 현재 상태로는 광고 예산 확대 판단에 사용하면 안 된다.

- 모바일 상세 도달률은 35.1%(80/228), 데스크톱은 61.1%(22/36)로 26.0%p 차이다. 모바일 카드 가시성·터치 영역·상단 정보 밀도를 우선 비교할 근거가 있다.

- 비회원은 신청 전에 로그인이 필요하므로 비회원과 카카오 회원의 신청률을 그대로 비교하면 로그인 구조 자체를 비교하는 셈이 된다. 회원상태 카드는 상세 열람 행동 참고용으로만 둔다.

### 2.5 검색·로그인 복귀

- 검색: 열기 14명 → 실행 4명 → 결과 노출 10명 → 선택 4명 → 상세 4명이다. 결과 노출이 검색 실행보다 많아 중간 비율이 250%다.

- 원인은 단계별 활성 사용자를 독립 합산하는 방식, 기간 중 추적 코드 버전 차이, 재방문·이미 로그인된 사용자 동작이 섞이기 때문이다.
- 두 카드는 순차 퍼널이 준비되기 전까지 메인 인사이트에서 제외하고 `추적 진단` 안에서 이벤트 도달 사용자로만 표시한다.

### 2.6 완료 신호

- 참여 신청은 비즈니스 완료 이벤트 1건이 있으나 `submit_start`, 단계 `complete`가 운영 응답에 없다.
- 현재 소스에는 `submit_start` 추적이 있으므로 기간 중 구버전 이벤트가 섞였을 수 있다.
- 참여 신청 성공 뒤 `golfjoin_apply_step_view · apply_step=complete`를 별도로 보내는 코드는 현재 없다. 완료 검증이 세 신호 모두 정상으로 바뀌려면 이 추적을 보강해야 한다.
- 새 모임은 제출 시작과 완료 추적 코드가 존재하지만 실제 완료 표본이 없다.

### 2.7 유입경로

- 직접 유입 250세션, `(not set)` 71세션이 대부분이며 `naver / display · hanoi_oct`는 2세션뿐이다.
- 현재 유입경로 응답은 방문량만 있고 상세 열람·신청 시작·신청 완료가 없다.
- 직접 유입과 `(not set)` 비중이 높아 UTM 규칙 없이 캠페인 성과를 비교하기 어렵다.
- v55에서는 소스·매체·캠페인별 `방문 → 상세 → 신청 시작 → 신청 완료`를 함께 반환하고, 표본이 충분한 유입만 확대 후보로 표시한다.

## 4. 자동 인사이트 판정 규칙

1. 수집일이 7일 미만이면 확정 표현을 쓰지 않고 `초기 신호`로 표시한다.
2. 구간 시작 사용자가 30명 미만이면 개선 우선순위 순위에서 제외한다.
3. 이전 기간의 실제 수집일이 없으면 이전 기간 증감과 `신규` 문구를 숨긴다.
4. 뒤 단계 사용자가 앞 단계보다 많으면 비율을 표시하지 않고 `독립 집계 · 순차 비교 불가`로 표시한다.
5. 상품카드가 아닌 CTA 섹션은 상품 선택률 순위에서 제외한다.
6. 모바일·데스크톱 비교는 각 그룹 방문 30명 이상일 때만 개선 후보로 사용한다.
7. 유입경로 확대 제안은 상세 열람 사용자 30명 이상과 신청 시작 1명 이상을 동시에 충족할 때만 만든다.
8. 신청 완료가 0명인 유입경로는 방문이 많아도 `확대`로 표시하지 않는다.
9. 모든 권고에는 `근거`, `수정 후보`, `수정 후 확인 지표`를 포함한다.

## 7. 완료 기준

- [ ] 화면에 100%를 초과하는 전환율이 없다.
- [ ] 이전 기간 데이터가 없으면 증감을 표시하지 않는다.
- [ ] 메인 방문과 빌더 내부 상세 열람이 분리된다.
- [ ] 가장 먼저 개선할 구간이 근거 수치와 함께 최대 2개로 표시된다.
- [ ] 모바일 개선 후보가 신청 시작까지 연결된다.
- [ ] 유입경로별 신청 시작·완료가 표시된다.
- [ ] 표본 부족 데이터는 순위·확대 권고에서 제외된다.
- [ ] 추적 검증 정보는 접힌 진단 영역에 남아 운영 점검이 가능하다.
- [ ] 데스크톱·모바일에서 공용 로딩, 필터, 기간 변경, 오류·빈 상태가 정상이다.
