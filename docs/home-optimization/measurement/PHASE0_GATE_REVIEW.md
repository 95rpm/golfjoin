- [x] 0단계의 목적인 현재 정상 버전 고정, 성능 기준선 수집, 병목 위치 확인, 복구 경로 확보를 완료했다.

- [x] 현재 정상 소스 경계는 SHA-256 `8A853CA11B9DED569067D2E45317B883E44452868E7FA8E01A2CCFAD6A17ACCC`, 크기 `2,731,639 bytes`다.

설명: 0단계는 성능을 이미 좋게 만드는 단계가 아니라, 현재 상태가 얼마나 느리고 왜 느린지 반복 가능한 숫자로 고정하는 단계다. 따라서 편차 20% 초과 자체는 0단계 실패로 숨기지 않고 후속 최적화의 명시적인 입력값으로 사용한다.

## 4. 0단계에서 후속 단계로 이관한 항목

### 1단계 — 테스트와 관측

- [ ] 로그아웃→로그인 복귀 중 회원 데이터 강제 지연 상태에서 알림톡 딥링크가 한 번만 열리는 E2E
- [ ] 나의 모임을 닫았다가 다시 열 때 회원 API 재호출 차이를 자동 기록하는 테스트
- [ ] PC Web Vitals와 상세 열기 시간까지 같은 계측 규칙으로 수집하는 `Performance.mark`/Observer 장치

### 2단계 — 실제 성능 개선

- [ ] 초기 데이터 도착마다 반복되는 전체 홈 렌더와 MD PICK 단독 렌더를 통합한다.
- [ ] 주요 실행시간의 3회 상대 범위를 20% 이내로 줄인다.
- [ ] 고정 8초 이미지 프리로드와 중첩 idle 대기를 제거한다.
- [ ] MD PICK 데이터 준비 후 첫 이미지 요청을 100ms 이내 시작한다.
