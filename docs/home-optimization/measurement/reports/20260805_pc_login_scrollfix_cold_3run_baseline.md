## 4. 최종 판정

- [x] 초기 HTML 처리, Load, 요청 수, 전송량, 이미지, MD PICK 지연은 성능 회귀가 없다.
- [x] 상세 모달 스크롤 코드가 실행되지 않는 일반 메인 진입에서 네트워크 폭증은 없다.
- [x] 마지막 로그인 API 종료만 기준보다 20.4% 늦다.
- [x] 같은 지연이 스크롤 수정 배포 직전 운영 표본에서도 나타나 스크롤 고정 코드가 직접 원인이라는 증거는 없다.
- [x] 공개·회원 일정 응답 뒤 `join_applications` 시작까지 2.17~2.62초 공백이 세 회차 모두 반복됐다.
- [ ] Performance trace에서 `hydrateBuilderApplicationJoinsFromGoogleSheet()`의 행 병합·캐시 동기화·upsert 비용을 측정한다.
- [ ] 처리 공백을 줄이기 전에는 회원 데이터 API를 더 병렬화하거나 DOM 렌더 순서를 바꾸지 않는다.
