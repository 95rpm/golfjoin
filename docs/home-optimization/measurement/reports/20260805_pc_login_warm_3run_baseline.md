# PC 로그인 웜 HAR 3회 통합 기준선

## 1. 채택 표본

| 공식 회차 | 파일 | 조건 |
|---|---|---|
| run01 | `20260805_pc_login_warm_run01.har` | HTTP·앱 캐시 웜 |
| run02 | `20260805_pc_login_warm_run02_retry.har` | 명시적 예열 직후 HTTP·앱 캐시 웜 |
| run03 | `20260805_pc_login_warm_run03_retry.har` | `home_stats` 예열 완료 확인 직후 HTTP·앱 캐시 웜 |

기존 `warm_run02.har`은 앱 캐시 만료와 홈 revision 변경이 겹친 진단 표본이며, 기존 `warm_run03.har`은 서버 지연 때문에 예열이 완료되지 않은 진단 표본이다. 두 파일은 원인 분석에는 보존하지만 공식 중앙값 계산에서는 제외한다.

## 2. 공식 3회 결과

| 지표 | run01 | run02 | run03 | 중앙값 | 상대 범위 |
|---|---:|---:|---:|---:|---:|
| 요청 수 | 117 | 116 | 117 | 117 | 0.9% |
| DOMContentLoaded | 940ms | 913ms | 832ms | 913ms | 11.8% |
| Load | 2,536ms | 2,754ms | 4,019ms | 2,754ms | 53.8% |
| 페이지 자체 마지막 요청 | 14,086ms | 19,413ms | 19,472ms | 19,413ms | 27.7% |
| 실제 전송량 | 956,189 | 548,015 | 557,071 | 557,071 bytes | 73.3% |
| 이미지 전송량 | 297,661 | 56 | 44 | 56 bytes | 일회성 아바타 영향 |
| 전송량 0 요청 | 99 | 100 | 101 | 100 | 2.0% |
| Cloud Function fetch | 3 | 3 | 3 | 3 | 0% |
| 보조 일정 API 시작 | 4,139ms | 4,955ms | 6,466ms | 4,955ms | 47.0% |
| 마지막 로그인 관련 API 종료 | 6,054ms | 5,525ms | 7,499ms | 6,054ms | 32.6% |
| MD PICK 지연 프리로드 | 12,092ms | 12,395ms | 12,470ms | 12,395ms | 3.0% |

상대 범위는 `(최댓값 - 최솟값) / 중앙값`이다. 마지막 요청은 취향맞춤 자동 순환 시점, 전송량은 run01의 일회성 아바타 다운로드 영향을 받아 핵심 합격 지표로 사용하지 않는다.

## 3. 확정된 사실

- [x] HTTP 캐시가 데워지면 CSS 8개와 JavaScript 44개는 세 회차 모두 재전송되지 않는다.
- [x] 현재 홈 카드 revision과 상품 대표이미지는 공식 run02·run03에서 재전송되지 않는다.
- [x] 앱 캐시가 신선할 때 초기 Cloud Function 경로는 3개다.
- [x] MD PICK 지연 프리로드 시작은 중앙값 12,395ms, 상대 범위 3.0%로 매우 일관적이다.
- [x] 따라서 MD PICK 대표이미지 지연은 이미지 서버 속도보다 고정 지연 실행 구조의 영향이 크다.
- [x] 원 홈페이지 `getEventTab.json`, `getEventGoodsList.json`은 세 회차 모두 수십 ms 이내의 소형 요청이다.
- [x] Supabase `productCC1.jpg` DNS 실패는 반복된다.

## 4. 남은 성능 불확실성

- [ ] Load 상대 범위가 53.8%로 목표 20%를 넘는다.
- [ ] 보조 일정 API 시작과 종료 상대 범위도 각각 47.0%, 32.6%다.
- [ ] HAR만으로는 JavaScript long task, 타이머 예약 지연, 실제 LCP 표시 시점을 확정할 수 없다.
- [ ] Performance trace 3회에서 Load 지연과 보조 API 예약 지연의 실행 원인을 분리한다.
