## 테스트 데이터 구조

운영 구글시트와 같은 세 가지 응답을 합성했다.

1. `new_schedule_applications`: A가 2명으로 생성한 원본 일정
2. `schedule_participant_summary`: A·동행·B의 공개 아이콘, 현재인원, 남녀 집계
3. B회원 전용 `join_applications`: 공개 B 아이콘을 현재 로그인 회원의 `나`로 연결하는 신청 행

공개 아이콘과 회원 신청 행은 `participantPreviewSeed`로 연결했다. ERP 상품번호와 행사번호도 생성 일정과 참여 신청에서 동일하게 유지했다.

## 발견한 실제 결함과 수정

### 현상

B가 참여를 취소한 뒤 서버 요약은 이미 `2명`, 빈자리 `2`로 정상인데 브라우저 참여자 배열에는 이전 B 공개 미리보기 아이콘이 남아 있었다. `나` 배지만 사라지고 익명 남성 아이콘과 현재인원 3명이 유지될 수 있는 상태였다.

### 원인

최신 `participant_summary`를 적용할 때 새 공개 아이콘을 기존 배열에 추가만 하고, 직전 요약의 공개 미리보기 아이콘을 먼저 제거하지 않았다.

### 최소 수정

`applyLightParticipantSummary()`에서 기존 참여자 중 생성자·회원 전용으로 실체화된 참여자는 보존하고, `participant_summary_preview` 출처의 이전 공개 아이콘만 제거한 뒤 최신 요약을 합친다.

이 방식은 다음을 동시에 만족한다.

- 활성 B 참여자는 회원 전용 신청 행으로 다시 연결되어 `나`가 유지된다.
- 취소된 B는 최신 공개 요약과 회원 신청 양쪽에 없으므로 제거된다.
- A 생성자와 A의 동행은 실체화된 생성 행이므로 유지된다.

## 안전 장치

- 테스트는 실제 계정, 휴대폰, 이메일, 쿠키를 사용하지 않는다.
- 모든 식별자는 `E2E_*` 또는 `example.invalid` 합성값이다.
- 알 수 없는 POST/쓰기 요청은 테스트 라우터가 409로 차단한다.
- 운영 HTML은 읽기만 하고, 배포 전 로컬 수정은 브라우저 메모리에만 주입한다.
- 합성 응답이 B회원 전용 생성 일정 조회에 A 행을 잘못 반환하지 않도록 공개/회원 조회 범위를 분리했다.
