## 4. 원인 우선순위

### 1순위 — 전체 홈·MD PICK 반복 렌더

PC 3회와 모바일 3회에서 초기 메인 스레드가 반복적으로 수초간 막혔다. 네트워크 응답이 빠른 run02·run03에서도 초기 long task 합계가 약 22초로 유지됐다.

- `scheduleHomeRender()` → `renderJoins()`
- `scheduleMdPickSectionRender()` → `renderMdPickSectionOnly()`
- 여러 데이터 도착 시점마다 큰 HTML 문자열 생성·비교·교체가 반복됨

### 2순위 — 내예약 첫 동기 렌더

`openJoinMyMenu()` 안에서 모달을 연 직후 `renderJoinMyMenu(member)`가 동기 실행된다. 세 번 모두 이 클릭이 602~769ms 걸렸고, API 응답을 기다리기 전부터 클릭 자체가 막혔다.

### 3순위 — 초기 레이아웃 공간 미확보

1.4~1.5초에 원 페이지 래퍼·히어로·골프조인 네비·MD PICK이 함께 움직이며 약 0.205466의 CLS를 만든다. 세 번 모두 같은 점수와 요소가 나타났다.

### 4순위 — snapshot fallback 재호출

run01만 `home_bootstrap_light`가 두 번 실행됐다. 다만 재호출이 없는 run02·run03에서도 초기 long task와 INP가 나빴으므로 주원인이 아니라 네트워크·렌더 편차를 키우는 보조 원인이다.
