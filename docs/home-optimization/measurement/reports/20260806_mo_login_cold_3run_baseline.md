원인 연결:

1. 홈 카드 JSON은 약 2초에 준비된다.
2. `scheduleMdPickImagePreload()`가 `setTimeout(..., 8000)`으로 8초를 기다린다.
3. 타이머 뒤에도 `requestIdleCallback`을 다시 기다린다.
4. 실제 대표이미지 첫 요청은 9.75~11.11초에 시작된다.
5. 요청 후 다운로드는 최대 약 0.26초 안에 끝난다.

따라서 “이미지 서버가 느리다”가 아니라 “브라우저가 요청을 늦게 보내도록 코드가 설계돼 있다”가 확정 원인이다.

## 6. 최적화 우선순위

### 1순위 — 8초 대표이미지 프리로드 지연 제거 또는 조건 변경

사용자가 곧 보게 될 첫 대표이미지는 데이터 준비 직후 요청하고, 화면 밖 국가·상품 이미지만 idle preload로 남겨야 한다.

### 2순위 — 데이터 도착마다 실행되는 전체 홈 렌더 통합

일정 API 응답 순서가 달라도 다음 API와 화면 반응이 밀리지 않도록 렌더 요청을 한 프레임·한 상태 커밋으로 합친다.

### 3순위 — `goodSeq=30001242`의 별도 지연 경로 확인

세 번 모두 같은 상품 이미지만 첫 13개보다 4~8초 늦었다. 어느 섹션 갱신이 해당 이미지를 추가하는지 계측한다.

### 4순위 — 조건부 중복과 Supabase 취소 검증

중복 URL의 initiator와 DOM 교체 시점을 연결하고, Supabase 이미지는 실제 화면 깨짐 여부를 별도 기능 테스트한다.
