## 5. 남은 최적화 우선순위

### 1순위 — Warm에서도 큰 단일 HTML

메인 HTML은 매번 490,537 bytes를 전송한다. Warm 총 전송량 중앙값 548,650 bytes의 약 89.4%다. 정적 CSS·JavaScript를 revision 자산으로 분리하면 재진입 때 가장 큰 추가 절감이 가능하다.

### 2순위 — `goodSeq=30001242` 고정 지연

주 MD PICK 이미지 묶음 이후 8,275~8,346ms 뒤에 별도 조회된다. 상대 범위가 0.9%에 불과해 네트워크 우연이 아니라 소스 타이머·후속 렌더 경로다.

### 3순위 — bootstrap 뒤 일정 API 시작 공백

중앙값 3,876ms이며 서버 응답 전이 아니라 프런트 실행 순서에서 만들어지는 공백이다. 앱 캐시가 있어도 로그인 개인화 완료를 늦춘다.

### 4순위 — 공용 이미지 304 왕복

고정 URL과 `max-age=3600` 정책 때문에 브라우저 캐시가 stale이 되면 26개 조건부 요청이 발생한다. revision URL과 immutable 캐시를 적용하면 본문뿐 아니라 왕복도 제거할 수 있다.

### 5순위 — 상품군 catalog 재검증과 Supabase 예외

immutable catalog는 loader의 `no-cache` 기본값 때문에 매번 304 재검증한다. Supabase `productCC1.jpg`는 세 번 모두 status 0이다.
