## 3. 원인 판정

### 대표이미지 서버가 주원인이 아니다

개별 대표이미지의 최대 다운로드는 세 번 중 가장 느린 경우도 151ms다. 반면 홈 카드가 준비된 뒤 첫 요청까지 7,535ms, 첫 묶음부터 마지막 묶음까지 10,035ms를 기다린다.

### 고정 타이머 체인이다

대표이미지 요청은 세 번 모두 다음 형태다.

1. 첫 7개
2. 약 5초 뒤 3개
3. 약 3초 뒤 1개
4. 약 2초 뒤 마지막 3개

첫 요청부터 마지막 요청까지 상대 범위가 0.22%이므로 네트워크 우연이 아니라 코드 타이머·후속 렌더 실행 순서다.

### 통계 API도 프런트 시작 지연이 크다

`home_stats` 서버 응답은 702~1,427ms로 변하지만 bootstrap 뒤 요청을 시작하기까지 중앙값 7,613ms를 기다린다. 서버 응답과 별개로 클라이언트의 delay·idle 정책을 먼저 개선해야 한다.

## 4. 전송량 구성

- 전체 전송량 중앙값: 약 5.72MiB
- 이미지 전송 중앙값: 약 3.80MiB
- JavaScript 전송 중앙값: 약 1.04MiB
- 상품 대표이미지 전송 중앙값: 약 1.27MiB

Cold 첫 진입에서는 이미지와 JavaScript가 전체 전송의 대부분이다. 후속 이미지 우선순위 조정과 정적 JavaScript revision 캐시가 모두 필요하다.
