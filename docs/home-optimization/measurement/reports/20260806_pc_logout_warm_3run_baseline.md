## 5. 확정된 원인과 우선순위

### 5.1 브라우저 캐시는 정상이다

- [x] CSS 8개와 JavaScript 44개는 세 번 모두 0 bytes다.
- [x] 상품 대표이미지 14개는 세 번 모두 0 bytes다.
- [x] 버전 홈 카드 JSON도 세 번 모두 0 bytes다.
- [x] 총 전송량 편차가 0.015%에 불과하다.

따라서 상품 대표이미지가 늦게 보이는 현상을 이미지 저장소나 다운로드 속도만으로 설명할 수 없다.

### 5.2 프런트 지연 타이머가 Warm에서도 지배적이다

- [x] 홈 카드 준비 후 첫 상품이미지 등록까지 중앙값 3.32초가 남는다.
- [x] 핵심 11개 이미지 묶음 뒤 마지막 `goodSeq=30001242`까지 중앙값 8.82초가 남는다.
- [x] 마지막 상품이미지는 중앙값 15.91초에 요청 목록에 들어온다.
- [x] 핵심 묶음→마지막 이미지 지연의 상대 범위가 1.7%라 우연한 서버 지연이 아니다.

Phase 2에서는 이미지 URL·레이아웃이 준비되는 즉시 우선순위 이미지부터 요청하고, 8초 계열 타이머를 제거하거나 유휴 작업의 안전장치로만 남겨야 한다.

### 5.3 Warm에서는 메인 HTML이 가장 큰 네트워크 자산이다

메인 HTML은 약 490,847 bytes로 Warm 전체 전송량의 약 93.7%다. 이미지와 외부 스크립트가 캐시된 이후에는 단일 HTML이 전송량 대부분을 차지한다. Phase 13에서 CSS·JavaScript 외부화와 HTML 경량화를 수행하면 재방문에도 직접적인 효과가 있다.

### 5.4 상품군 catalog는 불필요한 재검증 후보다

상품군 catalog는 버전 경로임에도 세 번 모두 304 / 13 bytes 재검증을 수행했다. 전송량은 작지만 왕복 요청은 남는다. Phase 2 또는 Phase 4에서 revision 경로의 불변성을 보장한 뒤 장기 캐시로 전환할 후보로 기록한다.
