# 3단계 소스 구조화·빌드 완료 보고서

## 결론

운영 중인 `golfjoin_main.html`의 동작과 배포 방법은 바꾸지 않고, 개발 원본만 기능별 파일로 나눠 관리할 수 있게 했다. 쉽게 말하면 큰 문서 한 장을 읽기 쉬운 여러 장으로 나눴다가 제출할 때 원래와 완전히 같은 한 장으로 다시 합치는 방식이다.

- [x] 운영 기준 파일과 조립 결과의 바이트 수가 같다.
- [x] 운영 기준 파일과 조립 결과의 SHA-256이 같다.
- [x] 단위검사 44/44를 통과했다.
- [x] 조립한 HTML을 직접 연 PC·모바일 E2E 12/12를 통과했다.
- [x] 운영 배포 절차는 게시판에 단일 HTML 한 개를 등록하는 현재 방식 그대로다.
- [x] 이번 단계 때문에 추가 배포할 파일은 없다.

## 무엇을 만들었나

개발 소스는 다음 책임으로 나눴다.

| 폴더 | 쉬운 설명 |
|---|---|
| `shell` | 게시판 HTML의 시작과 끝 껍데기 |
| `styles` | 화면 모양을 정하는 CSS |
| `markup` | 버튼·카드·모달 같은 HTML 구조 |
| `store` | 여러 기능이 같이 쓰는 상태와 설정 |
| `performance` | 성능 측정과 안전한 로그 |
| `loading` | 영역 로딩·전체 로딩·스크롤 잠금 |
| `member` | 로그인·프로필·찜·내예약·참여자·딥링크 |
| `data` | 홈 bootstrap 등 서버·GCS 데이터 읽기 |
| `detail` | 상품상세·여행기간·항공·Builder·참여 동작 |
| `sections` | MD PICK·취향맞춤·나의 모임 등 메인 섹션 |
| `boot` | 페이지가 시작되는 마지막 초기화 순서 |

현재 빌드 순서는 `source-manifest.json`의 15개 조각으로 고정했다. 아직 분류하지 못한 코드를 위한 `legacy` 폴더는 준비했지만, 1차 분류 후 활성 manifest에는 legacy 파일이 없다.

## 동일성 확인

| 항목 | 운영 기준 | 조립 결과 | 판정 |
|---|---:|---:|---|
| 파일 크기 | 2,767,496 bytes | 2,767,496 bytes | 일치 |
| SHA-256 | `B6D09D1AA648D567BBF0BB5CCBF4A98D9EA653E1648C28318C56596080C773FA` | `B6D09D1AA648D567BBF0BB5CCBF4A98D9EA653E1648C28318C56596080C773FA` | 일치 |

한 글자만 달라도 SHA-256이 달라진다. 따라서 이 결과는 구조를 나누는 과정에서 실행 코드·공백·줄바꿈까지 바뀌지 않았다는 뜻이다.

## 누락 방지 목록

자동 목록을 만들어 파일 이동 중 사라지기 쉬운 연결을 확인했다.

- 이름 있는 함수: 1,851개
- `window` 공개 대입: 47개, 고유 공개 이름 40개
- 정적 `window`/`document` 이벤트 연결: 35개
- 정적 이벤트 종류 중 `resize`: 6개

`resize` 등 여러 연결을 하나로 합치는 것은 동작 변경이므로 이번 단계에서는 건드리지 않았다. 7단계 선택적 렌더링에서 실제 호출 횟수와 시간을 측정한 뒤 안전하게 통합할 후보로 남겼다.

## 검증 결과

| 검사 | 결과 | 확인한 내용 |
|---|---:|---|
| 소스 조립 동일성 | 통과 | 메모리 조립본과 루트 기준 HTML의 bytes·hash |
| 빌드 재현성 | 통과 | `dist/golfjoin-main/golfjoin_main.html`이 같은 hash로 반복 생성됨 |
| 단위검사 | 44/44 | 경로 제한, 덮어쓰기 차단, 조립·목록 생성, 기존 성능 보조 코드 |
| 조립 산출물 PC E2E | 6/6 | 첫 이미지, 읽기 로딩, 공개·회원 진단, 연결 측정 |
| 조립 산출물 모바일 E2E | 6/6 | 첫 이미지, 읽기 로딩, 공개·회원 진단, 연결 측정 |

운영 `B6D09D1A...` 자체의 배포 후 기능 회귀 44/44도 이미 통과했다. 조립 산출물은 그 운영 파일과 바이트 단위로 같으므로 기존 메인·내예약·A/B 참여자·딥링크 동작도 같은 코드다.

## 빌드와 복구

```powershell
npm.cmd run home:source:verify
npm.cmd run home:build
```

첫 명령이 `match: true`인지 확인한 뒤 두 번째 명령으로 단일 HTML을 만든다. 빌드 도구는 루트 `golfjoin_main.html`을 자동으로 덮어쓰지 않는다. 어느 검사든 실패하면 `dist` 산출물을 배포하지 않고 루트 운영 기준 파일을 그대로 유지한다. 자세한 절차는 `src/golfjoin-main/README.md`에 기록했다.

## 보안과 공개 범위

3단계에서는 소스맵을 만들거나 공개하지 않는다. `source-manifest.json`에는 파일의 상대 경로·크기·hash만 있고, 의존성 목록에는 함수명·이벤트명·소스 위치만 있다. 회원 API 응답이나 개인정보는 기록하지 않는다.
