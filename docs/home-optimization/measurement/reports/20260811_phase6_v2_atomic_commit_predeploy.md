## 초보자용 설명

새 데이터는 상품 정보와 실시간 모임 정보 두 묶음으로 나뉜다. 어느 한쪽만 정상이고 다른 쪽이 잘못됐을 때 화면에 절반만 반영되면 가격·날짜·참여자 정보가 서로 어긋날 수 있다. 이번 작업은 변경 직전 상태를 복사해 보관하고, 두 묶음이 모두 정상일 때만 한 번에 교체한다. 중간에 하나라도 실패하면 복사해 둔 기존 상태로 즉시 되돌린다.

## 6-3 테스트 전용 Legacy ↔ V2 화면 비교

### 초보자용 설명

운영 스위치를 켜지 않고 자동 테스트 안에서만 새 데이터 길을 한 번 실행했다. 먼저 기존 방식으로 그려진 상품카드 결과를 저장하고, 같은 화면에서 V2 데이터를 한 번에 적용한 뒤 상품 순서·제목·가격·날짜·모집 상태를 다시 저장해 대조했다. 잘못된 파일도 테스트 안에서 의도적으로 만들어 기존 화면이 그대로 남는지 확인했다. 실제 운영 manifest와 구글시트는 변경하지 않았다.

### 비교 조건

- [x] 로컬 기능 플래그는 테스트 문서 안에서만 `true`로 설정했다.
- [x] 운영 Release root의 `browserReadEnabled=false`는 변경하지 않고, 테스트 네트워크 응답에서만 `true`로 복제했다.
- [x] 운영 주소와 GCS·Cloud Function의 읽기 응답만 사용하고 쓰기 요청은 만들지 않았다.
- [x] Legacy 렌더 완료 후 V2를 적용해 같은 브라우저·같은 시점의 결과를 비교했다.
- [x] PC Chrome 1440×1000과 Pixel 7 모바일 프로필에서 같은 검사를 실행했다.

### 비교 결과

- [x] PC Legacy → V2 카드 순서·제목·가격·날짜·표시 상태가 같다.
- [x] MO Legacy → V2 카드 순서·제목·가격·날짜·표시 상태가 같다.
- [x] MD PICK 국가·팩별 대표상품 결과가 같다.
- [x] 취향맞춤 테마별 TOP3 결과가 같다.
- [x] 마감임박·곧출발·맞춤조인·해외조인BEST 결과가 같다.
- [x] 테스트에서 `homeCards` 객체 뒤에 1 byte를 추가하자 bytes 검증이 차단했고, PC·MO 모두 `V2_FALLBACK`으로 전환하면서 Legacy 카드가 그대로 유지됐다.
- [x] 성공 시 manifest 1건과 static·live 2건, 총 V2 요청 3건만 사용했고 상태는 `V2_RUNNING`이 됐다.
- [x] 실패 시 후보·커밋 리비전이 남지 않았고 화면 데이터와 DOM이 바뀌지 않았다.
- [x] 전용 브라우저 검사 4/4와 전체 단위 검사 59/59가 통과했다.

### 원본 행 수 차이 해석

- Legacy 홈 카드 원본은 152행, 현재 발행 V2 홈 카드는 150행이었다.
- Legacy의 추가 2행은 새 `goodSeq`가 아니라 같은 상품의 이전 행사 행이며, 고유 `goodSeq` 수와 최종 대표상품 선택 결과는 V2와 같다.
- V2 계약은 Legacy의 빈 내부 상태값을 `available`로 정규화한다. 사용자에게 표시되는 카드 상태와 섹션 분류 결과는 동일했다.
- 따라서 원본 행 개수와 내부 기본값은 화면 회귀로 판정하지 않고, 고유 상품 수와 실제 표시 결과를 통과 조건으로 사용했다.
