## 초보자용 설명

기존에는 같은 상품군에 상품이 5개 있으면 여행기간을 보여 주기 위해 날짜 파일도 최대 5개를 따로 요청했다. 새 방식은 서버가 이 5개를 미리 상품군 파일 하나로 합쳐 두고 브라우저는 파일 한 개만 받는다.

새 파일이 없거나 내용이 맞지 않으면 오류 화면을 보여 주지 않는다. 브라우저가 즉시 기존 상품별 파일 요청으로 돌아간다. 따라서 서버를 먼저 배포하고 데이터를 만든 뒤 HTML을 마지막에 배포할 수 있으며, 중간 단계에서도 기존 화면은 그대로 동작한다.

## 구조와 안전장치

- 상품군 파일 경로: `web/product-availability/<availabilityRevision>/families/<familyRevision>/<familyId>.json`
- 캐시 키: `availabilityRevision:familyRevision:familyId`
- 저장 방식: JSON + gzip, 리비전이 포함된 변경 불가 URL
- 발행 순서: 상품군 날짜 객체 저장 → 저장본 재다운로드·검증 → 상품군 catalog root 전환
- 브라우저 검증: 스키마, 가용일 리비전, 상품군 리비전, 정확한 구성원 목록, 상품별 행사 수, 전체 행사 수
- 자동 복구: 파일 404, JSON 오류, 계약 불일치, 네트워크 실패 시 기존 goodSeq별 요청 사용
- 비정상 크기 차단: 원본 1MiB 초과 또는 2,000행사 초과 상품군은 새 객체를 만들지 않고 기존 경로 유지
- 단독 상품: 상품군 요청을 만들지 않고 기존 goodSeq 요청 유지

실측상 월별로 파일을 나누면 요청 수가 다시 늘고 가장 큰 상품군도 gzip 약 13.8KB에 불과하다. 따라서 상품군당 한 파일이 더 단순하고 빠르다.

- 새 상품군 파일이 없거나 일부만 만들어져도 새 HTML은 자동으로 기존 상품별 요청을 사용한다.
- 즉시 복구가 필요하면 HTML만 직전 정상본 `E454782A9F112FBA63F5CC3A426BFFE6205B481F470CAC085981A30317A4A391`로 재배포한다.
- 새 GCS 객체는 리비전 경로의 변경 불가 파일이라 삭제하지 않아도 기존 HTML에 영향을 주지 않는다.
- 서버를 되돌려야 할 때만 직전 서버 소스를 다시 Cloud Function으로 배포한다.
